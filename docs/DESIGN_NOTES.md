## 2026-09-29 第一階段設計（邏輯日 → 期間 → 設定版本化）

由上面的決定和規格推導，實作前記下：

1. **設定版本**：整份預算設定（收入、發薪規則、邏輯日起點、分類、時段、固定項目）存成一筆版本，帶生效日（邏輯日）。
   - 一般儲存：生效日＝明天。今天建立、明天生效的版本，對「今天還沒回報的時段」取較低值，調降的差額進待分配池（「釋出的錢不自動變成花費額度」）。
   - 更正：生效日可以是過去，但必須填原因，版本標記為更正。
   - 分類、時段、固定項目的 id 在各版本間保持不變（回報靠 id 對應）。
   - 舊的覆寫式設定在第一次讀取時匯入成一筆「從最早開始生效」的版本；舊資料表這一版先保留、不再寫入，下一版再移除。
2. **每日額度不落地**（§2.2）：原本期間建立時產生並存進資料庫的「每日時段額度、分類額度、固定支出」三張快照表移除，改成每次重播時由「當天有效的設定版本＋行事曆」算出來。
   - 月額度、每日類的整期額度、收入、固定支出：用**期間第一天有效的版本**（期中改了下期才生效）。
   - 每個時段每一天的金額：用**那一天有效的版本**。期中版本造成的排程增減，在待分配池記一筆「設定變更」，日期為生效日。
3. **發薪規則**：每月 X 號；遇假日「不調整／往前推到最近的工作日／往後推」。工作日＝行事曆上不是假日的日子（補班日算工作日），與餐費平日／假日共用同一份行事曆。
   - 期間起訖存在資料庫；新期間從上一期結束隔天開始（有斷層時從「今天以前最近的發薪日」開始）；結束日＝下一個預定發薪日前一天。
   - 可手動覆蓋本期的下一個入帳日（＝改本期結束日），只能改進行中的期間。
   - 已開始的期間不受規則變更影響。
4. **事實只新增**：回報、待定區調整、薪資調整、資產加減都加上「取代哪一筆（ReplacesId）」與「作廢（IsVoid）」。修改＝新增一筆取代舊的；刪除＝新增一筆作廢紀錄。重播只看沒被取代、也不是作廢的那些。
5. **邏輯日**：凡是「今天是哪天」都依邏輯日：時間往前推「邏輯日起點」再取台北日期。起點本身屬於設定版本。
6. **金額改用 decimal**（§0.6）：資料庫欄位與所有計算一起換。
7. **暫不動、之後階段處理**：
   - §7「% 算在扣掉固定支出後的餘額」：目前仍是佔收入 %，跟 §7/§8.2 的分配設定畫面一起改，避免使用者現有的 % 意思突然改變。
   - §10.1 超支平均攤：目前依時段金額比例攤，做 §10 時改。
   - 存款帳戶餘額目前仍是存下來的數字（資產加減會直接改它），§5／§12.1 帳戶模型時改成由對帳事實計算。
   - 行事曆的手動覆寫（請假、颱風假）視為對未來的設定：只能改今天以後的日子。

## 2026-09-29 第二階段：帳戶模型與對帳（§5、§12.1）

- 帳戶類型：銀行、現金、電子支付、信用卡（負債，餘額＝欠款）。移除帳戶只封存。
- 帳戶餘額不存（§2.2）：最近一次對帳 + 之後的轉帳、繳卡費、資產加減、有記付款帳戶的回報。
  舊版直接存的餘額第一次讀取時轉成一筆完整的「期初」對帳。
- 互轉、繳卡費：事實、只新增；淨額不變，所以對帳時不用特別扣除。
- 對帳存各帳戶實際餘額；只有填了所有帳戶的「完整對帳」才和預期比。
  預期淨額＝上一次完整對帳淨額 + 兩次之間已知收支（發薪收入含薪資調整、每日時段實際或照預算、額外花費、到期固定支出、資產加減）。
  差額在對帳的登錄時間重播：多的進待分配池；少的走超支規則（可選先從池扣，其餘攤到之後所有每日類時段）。
  補回報會讓預期值改變、差額自動縮小；差額會影響之後的額度，所以重播迭代到穩定。
- 差額超過本期變動預算 30%：試算時提醒是否漏記大額 / 固定支出，勾選確認後才能送出。
- 回報可選付款帳戶；信用卡欠款與「本期刷卡（下月卡費預估）」由此推算。
- 應收應付（§14）、投資買賣帶入對帳：做 §14 時補上；目前投資買賣請用「資產加減」記。

## 2026-09-29 第三階段：依 % 分配（§7）與餐費設定畫面（§8.2）

- % 基準可選「整個月收入」或「扣掉固定支出後」（規格 §7）。**舊設定維持「整個月收入」**，免得現有的 % 意思突然改變；
  新使用者預設「扣掉固定支出後」。切換時自動換算每個分類的 %，金額不變。
- 分類可以不勾「用 %」改填固定金額；可設底線（給範本 / 分配器用）。% 總和超過 100% 擋住儲存。
- % 零頭：各分類先無條件捨去，再用最大餘額法補到「基準 × % 總和」的整數。
- 非固定收入：% 基準用上期實際收入（含薪資調整）；還沒有上期時用設定值，並提醒。
- 餐費表：自己設定 / 自動分配兩種模式同一張表。即時合計（平日小計、假日小計、合計對額度）由後端用同一套計算試算。
  自己設定模式超過額度時，前端停用儲存，後端也擋。
- 自動分配：權重、假日倍率（或每格假日權重）、鎖定、底線、取整單位存在設定版本裡；計算呼叫 `Allocator.Allocate`。
  - 分配器由使用者實作（§8.1）。**目前丟 `NotImplementedException`**：重播時該分類改用手動金額，並在今天 / 總覽頁提醒；
    設定頁按鈕顯示「分配器尚未實作」。
  - 期中改自動分配設定：以「整期額度 − 這段之前已排掉的」對剩下的平日 / 假日天數重算（§4.1）。
  - 分配零頭進待分配池時標記來源（「餐費自動分配的零頭」）。
  - 微調（＋／－）：以該格 ± 取整單位鎖住重算，列出其他格實際變化（前後相減），確認後反推權重、不留鎖定。
  - 手動 → 自動：以目前金額反推權重（每格 ÷ 平日第一格），假日格用自己的權重，讓切換當下數字不跳（A12 的預期值由使用者驗證）。
- 注意：正式站目前的餐費排程可能已經超過額度（舊資料沒有這個檢查），下次儲存設定前要先調整。

## 2026-09-29 第五階段 a：超支攤提、護欄、全天例外、月結（§9.3、§10、§12.2）

- 超支攤提改成「之後每天平均扣」（§10.1）：先把金額平均分到剩下的天數（整數、零頭給前面的天），
  每天再依當天各時段額度比例分到時段。回報畫面顯示「接下來 N 天每天少約 X」。
- 護欄（§10.2）：每個時段最多扣到原本額度的 50%（`GuardrailFloorPercent`，設定版本裡可改，預設 50）。
  攤不下去的部分讓使用者選：從待分配池扣（預設）、延到下一期、分兩期、從存款吸收（選帳戶）。
  選擇存成事實（池轉入 / 期間結轉 / 資產加減），用 `SourceEntryId` 連回那筆回報；刪掉回報時一起作廢。
- 全天例外（§9.3）：「這天全部 0」「這天全部照預算」＝把這天還沒回報的每日時段各補一筆回報，可以個別刪。
  未來的日子不能按。
- 月結（§12.2）：
  - 本期最後 5 天（發薪日前 5 天）起可以月結；月結前要有一次最後 7 天內的完整對帳。
  - 報告：結果（收入 − 所有支出，含對帳差額）、上期結果、超支最多的時段、目標進度、各時段平均實際花費。
  - 決定：結餘帶進下一期或轉存款；超支下一期扣、分兩期、或從存款吸收。可一起改下一期的時段金額（寫成下一期生效的設定版本，超過預算會擋）。
  - 月結寫一筆不可改的快照，本期鎖住（不能再回報、對帳、改）。之後補登到已月結期間的花費，改記在今天，備註「補登 M/d」（§4.2）。
  - 上一期沒月結時，今天頁頂端擋住（可以「晚點再說」），不會自動替使用者月結。

## 2026-09-29 第五階段 b：滑卡確認（§9.2）

## 2026-09-29 第五階段 c：範本、新手引導、一次性提示（§20）

## 2026-09-29 第六階段 a：罐子（§11）

現況（改之前）：待分配池只有「待定區調整」（`PoolTransfer`：沒分類＝錢進出池子、有分類＝分配給分類）；
年繳 / 季繳固定支出在繳費那個月一次扣全額；資產頁的「目標」是看資產總額的進度，和預算無關。

做法：
- 罐子（`Jar`）是容器：預約支出、年繳預留、儲蓄目標。名稱、目標、到期日可以改，關閉時剩下的錢回待分配池。
  （和帳戶一樣是容器，直接修改；錢的進出才是只新增的事實。）
- 錢進出罐子一律記成本期的待分配池調整，帶 `JarId`（負數＝存進罐子）。罐子餘額不存：
  ＝ 這些調整取反的合計 − 從罐子付掉的（回報上的 `JarCovered`）。池子和罐子永遠對得起來，刪掉調整就還原。
- 預約：登記當下從池子扣；池子不夠的部分攤到之後每天（和超支同一套、護欄照樣適用），再攤不下才讓池子變負。
  付的時候在「額外花費」選從這個罐子付：罐子付得起的部分不算進預算；實際比預留多的部分照超支規則，比預留少的回池子（結餘規則）
  並自動關閉罐子；刪掉那筆回報會一起還原、重新打開。
- 年繳：建立時提撥一期，之後每一期開始時自動提撥（預設目標 ÷ 12 無條件進位，可自訂），到目標為止。
  到期付款時選從罐子付；付完下次繳費日往後一年，繼續提撥。
  可以直接從年繳 / 季繳固定支出轉過來：那個固定支出從明天起停用（存一份新的設定版本），避免重複扣。
  既有的年繳固定支出**不會自動改**，照舊在繳費月一次扣（保守，使用者自己決定要不要轉）。
- 儲蓄目標：手動存入 / 拿回；可以設自動規則「時段省下的錢自動存 X%」（各罐子合計不超過 100%），這筆存入掛在那筆回報上，刪回報時一起作廢。
- 分配順序（§11.2）：分配剩餘的畫面先列「有到期日、還沒存滿」的罐子，快到期的在前，可以一鍵補；
  第 2 點「其餘依使用者設定的比例或上限」目前只有「全部給一個分類 / 依比例分到全部」，罐子的比例上限先不做。
- 對帳：從罐子付的錢也真的從帳戶出去了，所以對帳的預期支出包含 `JarCovered`。
- 資產頁的「目標」維持原樣（看資產總額），和罐子的儲蓄目標是兩回事；之後若要合併再討論。

## 2026-09-29 第六階段 c：共用支出（§14）

現況（改之前）：回報只有「我花了多少」，代墊的錢只能當成花費，對帳時會變成差異。
- 應收（`Debt` Receivable，資產）/ 應付（Payable，負債）與收回 / 還款（`DebtSettlement`）都是只新增的事實。第一版對象只是名字。
- 回報時勾「和別人分帳」，上面的金額填**我的份**：
  - 我全付：預算只扣我的份；多付的記應收，從同一個付款帳戶出去（不算花費）。
  - 對方先付：我的份照扣預算，記應付；錢沒從我的帳戶出去，所以這筆回報不記付款帳戶。
  - 刪掉回報時，分帳出來的應收應付（和已經記的收回 / 還款）一起作廢。
- 資產頁「應收應付」：別人欠我 / 我欠別人的合計、每一筆「收到還款 / 還錢」（選帳戶）、手動記一筆借出 / 借入（不是花費）。
- 帳戶餘額與對帳：代墊多付的出帳、收回進帳、還款出帳都算進帳戶推算；對帳的「已知收支」也包含
  （應收成立 −、收回 +、應付成立 +〔預算已經算了我的份，但錢沒出去〕、還款 −），所以不會被當成沒交代的差異（§14 第 4 點）。
- 淨資產數字目前不把應收應付算進去（分開顯示），之後要合併再說。
- 第二版分享連結、加好友：還沒做。

### 順手修的 bug（程式錯誤，不是規則問題）
- 帳戶餘額推算時，先篩「有付款帳戶的回報」再判斷有效，作廢 / 取代的紀錄不帶付款帳戶被篩掉了，
  所以**刪掉或改回報後，原本那筆的付款還是算在帳戶上**（本期刷卡預估也一樣）。改成連作廢紀錄一起讀，加了回歸測試。
- 測試用時鐘換日期時計數器會歸零，造成「後建的紀錄時間比先建的早」，改成不歸零。

## 2026-09-29 第六階段 d：分期（§15）

現況（改之前）：只有設定裡的固定支出（每月 / 季 / 年），沒有「共 N 期、會減少的負債」。
- 分期（`Installment`）與提前還款（`InstallmentPrepayment`）是只新增的事實；繳款表不存，每次由 `InstallmentSchedule` 推出來。
- 兩種輸入：簡易（每月 X 元共 N 期，當成 0 利率）／細部（本金、年利率、期數、手續費）。
  - 細部用本息平均攤還，月利率＝年利率 ÷ 12；0 利率＝本金 ÷ 期數。手續費總額平均加在每一期（零頭在第一期）。

- 每期繳款＝那一期的固定支出，算在使用者指定的固定類別；**在算 % 之前就加進來**，所以「扣掉固定支出後」的基準會跟著變小（§7）。

- 提前還款：從資產付，負債（剩下的本金）減少，不算花費、不扣預算；選「期數變短（每期不變）」或「每期變少（期數不變）」。
  期數變短時，還沒繳的手續費加在新的最後一期（保守：手續費照樣要付；各家銀行規則不同，實際以帳單為準）。
  提前還款會算進帳戶餘額推算與對帳的已知收支。
- 每期繳款不綁帳戶（跟其他固定支出一樣），對帳時以「固定支出」算進已知收支。
- 「還款來源可為存款加部分月薪」：提前還款選帳戶；要從這期預算撥一部分，先用「分配剩餘」或罐子存好再還。
- 年繳：見第六階段 a 的年繳罐子。

### 21.3 App 鎖與登入裝置
- App 鎖：每台裝置自己開，用平台 passkey（iPhone 是 Face ID）。打開 app、或離開超過設定分鐘數回來時要解鎖。
  驗證在裝置上做，**只擋畫面**（規格也這樣寫）；離線資料（快取）沒有加密（規格未定，先不做）。
- 登入裝置：DayCap 自己發一個裝置 cookie（隨機值，HttpOnly），用它記「登入中的裝置」。可以登出某一台、或「登出其他所有裝置」。
  - 為什麼不用 token：Mini-SSO 的 access token 會一直被 refresh 換新，只封 token 封不住。
  - 被登出的裝置下一個請求會收到帶 `X-DayCap-Revoked` 的 401，前端接著呼叫 Mini-SSO 登出（**連 refresh token 一起撤銷**），回到登入頁。
  - 限制：Mini-SSO 沒有「撤銷這個人所有 refresh token」的 API；如果有人刻意清掉 DayCap 的裝置 cookie、又還握有有效的 refresh token，
    還是能以「新裝置」進來。要完全撤銷需要 Mini-SSO 增加這個功能（沒有動 Mini-SSO，因為其他站也在用它）。
### 21.4 離線使用
- service worker 快取 app 本體與「本期」資料（先走網路，失敗才用快取），沒網路也打得開。
- 沒網路時滑卡確認先排隊在這台裝置，連線後依序送出；頂端顯示「離線中 / 還有 N 筆等著送出」。
- 衝突規則（未定，先保守）：送到伺服器的順序就是生效順序；同一時段兩台都回報，後送到的取代先送到的（舊的留紀錄）。
  伺服器拒絕的（例如那期已經月結）不會默默丟掉，列在頂端讓使用者看到。
- 登出時清掉離線快取。

## 2026-09-29 第八階段：旅遊與外幣（§17）、收入中斷（§18）

### 旅遊
- 一趟旅遊（`Trip`，事實）＝一段日子＋一筆旅遊預算。旅遊預算是一個預約罐子：建立時從待分配池預留（池子不夠的攤到之後的日子）。
- 旅遊的日子：每日時段的額度歸 0，省下來的額度在「建立旅遊那天」一次回到待分配池（建立前已經過去的日子不回溯）；
  這幾天的檢核畫面顯示「旅遊中」，花費記在額外花費，預設從旅遊預算付。
- 只能從今天或之後開始（過去的日子照原本的額度算）；日子不能重疊；期間內已經有時段回報時要先刪掉。
- 結束旅遊：進行中＝結束日改成昨天（今天起恢復每日時段）；還沒出發＝整趟取消。旅遊預算剩下的回待分配池。
### 外幣
- 額外花費可以勾「外幣」：幣別、外幣金額、匯率 → 換成台幣記帳（四捨五入到元）。**匯率來源未定，先由使用者自己填**，
  採用回報當下的值（存在那筆回報上，之後匯率變動不影響）。旅遊中會帶入旅遊設定的幣別和匯率。
### 時區（§3.3）
- 回報會記下裝置當地的時區（例如 Asia/Tokyo）。**邏輯日目前仍以台北時間計算**：到日本、韓國差 1 小時影響很小；
  到時差大的地方時「今天」可能差一天——要完整依當地時間切時段，需要讓整個期間計算帶時區，列為之後的工作。
### 收入中斷
- 「這期沒有收入」＝記一筆薪資調整把這期收入扣到 0（刪掉那筆就恢復）。
- 「從存款撥入預算」＝待分配池補進一筆（只是讓這期可以花存款的錢；實際花掉時帳戶才減少，所以不另外記帳戶異動，避免重複）。
- 「照目前花法，存款還能撐幾天」＝可動用資產（銀行＋現金＋電子支付 − 信用卡欠款，不含股票）÷ 最近 30 天平均每日實際花費
  （時段回報的實際值、沒回報的照預算、額外花費、當天到期的固定支出；今天不算）。

## 2026-10-06 固定支出的自動轉帳與定期定額

- 設定頁每一筆固定支出多了「扣款日自動」：不自動（只扣預算，原本的行為）／轉到某個帳戶／定期定額某一檔股票，以及「從哪個帳戶扣」。
  存在設定版本裡（`FixedItemDoc.FromAccountId / ToAccountId / HoldingId`），跟著版本生效。
- 轉到帳戶：扣款日當天自動記一筆帳戶互轉（`AccountTransfer.AutoKey = fixed:{項目}:{日期}`，同一期只做一次）。
  對帳時：預算把它當固定支出扣掉了，但錢還在自己的帳戶裡，所以已知收支會把這筆加回來，不會變成沒交代的差額。
- 定期定額：扣款日（休市就下一個交易日）用**當天收盤價**買整數股（零股），花費＝股數 × 收盤價（四捨五入到元），
  零頭留在帳戶；持股股數、平均成本同步更新；扣款帳戶餘額減少。紀錄在 `HoldingPurchase`（`AutoKey = dca:{項目}:{日期}`）。
  - 收盤價：證交所 STOCK_DAY、櫃買 tradingStock 的每日成交資訊（收盤價要等收盤後資料源更新，約下午兩點後），還查不到就下次再試。
  - **手續費沒算**（各家券商不同，有的定期定額 1 元起）；手動填價格的標的不能定期定額（抓不到當天收盤價）。
- 什麼時候執行：每小時背景跑一次，打開資產頁時也會先跑；只往回補最近 31 天，用扣款日那天有效的設定版本
  （一般儲存是明天起生效，所以不會回頭補；要補今天以前的要用「更正過去」）。
- 資產頁持股那列顯示「定期定額：每月 6 號 9,000，從 玉山 扣款」和上次用什麼價格買了幾股。
